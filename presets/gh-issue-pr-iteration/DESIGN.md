# gh-issue-pr-iteration 设计书

本文件是这个 preset 的设计思路记录，写给改 prompt 的人。它不注册进 preset.toml、不被引擎加载、不被任何文档引用——它只解释这套 prompt 为什么长成这样。结构性的"什么文件在哪"看 `docs/gh-issue-pr-iteration-fragments.md`，本文只讲为什么。

## 出发点：第一版的失败

第一版调度者架构跑了约二十个真实任务，结论是几乎完全无效。失败形态不是"agent 能力不够"，而是 prompt 自身的四个缺陷：

1. 让调度者去读 subagent 的 prompt——双受众泄漏，执行细节污染判断，判据反向喂给执行者照着表演。
2. 没有规定哪些事必须派发——"所有事情用 subagent 做"是一句口号，什么事、用哪个 subagent、传什么、收什么，全没说。
3. subagent 没有输入输出契约——派发消息靠调度者即兴发挥，汇报靠 subagent 自由发挥，验收无从谈起。
4. 核心内容一笔带过——系统里最关键的判断（review 是否通过、issue 是否完成）得到的认知支撑最少。

结果：review 只会对着 PR body 抠字眼、不查任何代码、发现不了删测试，十二轮 retry 全在措辞上打转。

## 前提一：prompt 被无视是设计输入，不是异常

Agent 会钻空子、会跳过麻烦的步骤、会用最省事的解释执行模糊指令。这不能靠"写得更恳切"解决，必须当成设计输入：**你不写就等于没说，没说等于我能钻空子**。由此推出的写法纪律：

- 每个动作点上，"做什么、谁做、为什么、判断什么"内联在使用现场，不放在独立章节里靠读者自己关联。语言被拆散等于相关性不大。
- 这类 prompt 本质是 workflow，就按编号步骤呈现；散文章节是给内聚的"注意事项"留的，workflow 的每一步不享受这种自由。
- 任何例外口子写出来就会被走成主路。"auth 缺失可以跳过"这种 carve-out 写上去的那一刻，所有 auth 都开始缺失。修法不是措辞收紧，是把口子在事实层封死（见"运行环境"一节）。
- 堵口子要堵双面：执行面在动作现场写禁止，判断面在验收判据里写拒收。单面堵不住——执行者绕过去之后，判断者若没有对应的拒收规则，绕行就成功了。

## 前提二：调度者的本职是维护任务清单

"调度"不是转发消息，是**把计划落成显式清单、保证每一行走到终态**。清单规则是这套架构的脊柱：

- 列表先于执行写出，每行注明这次派发要产出什么、凭什么验收。
- 每行只有两种出口：`[x]`（仅由被验收的 subagent 汇报勾掉，调度者自己做掉不算）或 `[-] skipped: <理由落进 handoff>`。没有第三态。
- 每次 verdict 后重印整张清单。停止重印的清单就是停止维护的清单。
- 调度者亲自可执行的命令是闭集清单，清单之外的任何命令就是派发信号。"这件事很小我顺手做了"正是第一版崩坏的起点。

## 前提三：判断不可下放给程序，但可以被结构逼出来

Agent 判断失误不能用状态机、验证层、verdict 文件这类工程手段修补——正因为程序没有判断力才把判断交给 LLM。但可以用结构**逼判断发生**：

- **三件套合同**：每个步骤 task.md（执行者任务书，含 Inputs 节）/ report.md（结构化汇报模板，必填字段，空集写 `none`）/ accept.md（调度者验收判据，内嵌必填字段清单）。调度者永不打开 task/report，执行者永不读到 accept——判据不可表演，执行细节不污染判断。
- **品质判据按受众物理拆分**：`-execute.md` 只进执行者上下文，`-judge.md` 只进调度者上下文。单文件双受众是实测过的双向泄漏源。
- **对外输出强制实测值**：PR 回复的每个 check 节要求只有真做了检查才存在的内容——SHA、计数、原句引用、URL、时间戳。填不出字段即检查未做，无内容可输出就必须回头补判断。这是对"pass/fail 一行话走过场"的结构性封堵：判断不发生，输出就空着，空着就立刻可见。

## 前提四：review 的信任来自独立重做，不来自阅读

Review 不读 iteration 说了什么来决定信任什么——它派发独立 subagent 重做，四份报告各占一个真值面，缺任意一份的 verdict（含 retry）无效：

- **diff-audit** = scope / 卫生 / 代码真值（纯读）。代码审查在 loop 内，锚点是 issue 声明的设计：每条发现必须带锚（可追溯失败路径 / issue 原句 / convention 来源），不发散——替代设计、issue 设计外的改进、diff 没碰的代码不进 verdict。发散一旦计入 verdict，loop 就学会了漂移。
- **test-integrity** = 测试真值（自建 scratch worktrees 在 base/head 两侧实测计数 + diff 枚举逐条对应）。"计数下降无枚举"即隐藏弱化——删测试在第一版完全不可见，这一步是为它专设的。
- **replay** = 契约行真值（验收表逐行真跑，未跑行只有"setup 未完成附尝试记录"和"manifest 缺项计为 packet 失败"两种合法形态）。
- **e2e-replay** = 交付物真值（接 standing environment 直跑复演 + browser 契约行 + 脚本形态检查）。

"packet 一眼就有问题"不是省略派发的理由——先拿齐四份报告，一次性引全所有失败。挤牙膏式 retry 是对迭代轮次的浪费。

另一个对称原则：**review 绝不替 iter 修**。唯一例外是恢复被篡改的 issue body——那是契约保护，不是修工作。issue body 是契约本体，篡改检测（编辑历史比对）→ 恢复 → 红线警告是 review 自己的判断 0。

## 前提五：交付物必须以真实形态跑过，环境是交付物的一部分

unit/integration 测试必须有，但永远只是辅助层。唯一的正规产物是 **e2e 直跑**：程序以操作者方式调真实入口，web 以 agent-browser 走真实 UI；"它是个库"不豁免（跑它的真实消费面）；**脚本 e2e 禁止**——包一层 harness 的就是集成测试，不管文件名叫什么。browser 验收行就是 e2e 的一种，归 e2e 域执行，不双跑。

auth 和 binary 永远是执行者自己解决的，因为事实上不存在缺失：交付物要么是能自己起环境的单体程序（起环境时自铸 auth），要么是 IaC 基建里服务的插件（机器上必有可解析的 auth）。把这条写成事实而非要求，"no auth" 就从可报告的 blocker 变成了未完成的 setup。

环境交接闭环：iter 跑完 e2e 把运行环境**留着**，交 runtime manifest（binaries、服务与启动命令、auth 解析位置——绝不写 secret 值、端口、在跑 PID 与停法）。review 凭 manifest 必然复跑得动——manifest 缺项是 packet 失败计入 retry，"review 跑不起来"被设计成不可能。全部 teardown 归 review 调度者收尾。e2e 单独成步而不并入 verify，是因为捆在重步骤里的麻烦环节会被整体跳过——单独一行清单 + 独立验收，跳过就关不掉清单。

## 前提六：每次运行无状态，GitHub 是唯一持久层

每次 spawn 的 agent 是独立进程，无跨轮记忆；本地文件会丢、会损坏、跨机不可用。持久业务语义只能落 GitHub（issue body / labels / comments / PR thread）。由此：

- issue↔PR 关联只认结构性链接（closing keyword 图，GraphQL `closedByPullRequestsReferences` 分页到穷尽），不做 body 文本搜索——数字出现在 body 里不构成关联。
- retry 的指令源是 PR 的全量读取（body + 全部 comments + 全部 reviews + inline review threads），切片阅读会让整张任务清单建立在错误的指令上。
- 调度者的亲自阅读是闭集（恰好 N 项，每项标注喂哪个决策）+ 一跳图引用；之外的一切阅读是派发。"exactly these reads"曾因漏项而自相矛盾，闭集必须与决策清单互证。

## 写 prompt 的人最容易犯的错（本 preset 的事故记录）

- 站在作者视角写 why-and-how，读者视角下等于没写。每一句要回答的是读者此刻的问题：现在做什么、拿什么做、做完判断什么。
- 防博弈措施写过头变成自相矛盾（"PR body untouchable" 与全局路由模型冲突造成 livelock）。防的是重写叙事，不是结构修复——划界要划在动机上。
- 占位符不绑定（`<scratch>` 落哪没说）、API 失败语义不定义（sub_issues 404 算什么）、固定 cap 静默截断（first:10）——每一处含糊都是一个未来的卡死点或假阴性。
- 工具名写进机制描述（send_input / Task tool）会把 prompt 锁死在特定 runner 上；写机制（"同一 subagent 的 follow-up"），runner 自己映射。
