# 选题确定

## 素材结构

素材围绕一个单一中心问题展开：RFC #547 为什么不能被理解为若干字段和校验器的叠加，而必须被理解为从定义编译、实例创建、调度推进到恢复解释的一次权威链重构。现有材料虽分散于类型、任务树、工具、gate、不可变定义和去 GitHub 化等多个领域，但这些领域共享同一根因：同一业务事实在不同时间和入口被重复解释。

## 跳过方向性选题发散

用户已经明确指定文档必须完整回答“实现什么”和“为什么实现”，并禁止写概要。另行选择更窄的单点主题会删掉能力之间的因果关系；选择历史复盘或 issue 清单则会偏离问题。因此不进行五方向题材竞争，直接采用“系统能力与必要性的完整因果说明”这一多中心单主题形态。

## 最终写作方案

- **形态：** 多中心一主题的技术分析报告。
- **中心判断：** RFC #547 实现的不是一组扩展字段，而是一条从可变字符串定义到不可变、类型化、可恢复执行实例的单一权威链；只有这条链闭合，递归任务、typed binding、tool/gate 与 resume 才不会互相制造第二事实源。
- **写作范围：** 完整解释成功路径、失败路径、事务边界、恢复语义、领域 owner、外部依赖、明确不实现的内容以及 current/target 差异。
- **禁止形态：** 不按旧 issue 或 D1–D10 编号复述；不复制 SYNTH 的段落、完成时态或旧状态；不把 191 项需求和 36 条 seam 写成实现完成率；不以术语清单代替机制说明。
