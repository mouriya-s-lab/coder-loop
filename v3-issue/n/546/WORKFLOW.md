# RFC #546：调查、裁决与滚动重拆 workflow

> 本文件只维护阶段、gate、问题树与当前账本，不定义产品语义。产品权威见 [RFC.md](RFC.md)，事实索引见 [EVIDENCE.md](EVIDENCE.md)。

## 1. 主 agent 与 subagent 的职责边界

### 主 agent

- 只维护目标、阶段、问题树、裁决请求与正式 RFC/证据索引。
- 只读取 subagent 的正式报告，不自行钻入源码、日志或实验细节。
- 对每个新增机制追溯到已确认问题；证据不得自产需求。
- 不实现代码、不创建 worktree、不提前重拆 issue。
- 每个 gate 后归并有效信息并清退中间报告；正式文档包括 README/RFC/A/EVIDENCE/WORKFLOW/OVERALL（OVERALL 承载工程总体；A 是操作员要求的独立长篇设计论证），此外不再新增 Markdown。

### subagent

- 每次只调查一个具体问题，读取真实系统并给出路径、命令、结果与确定后果。
- 区分需求、实现事实、实验事实和建议；不得替操作员裁决产品语义。
- 以报告回复主 agent；不修改 RFC、阶段、问题树或正式账本，除非任务书明确授权。
- 不把局部反例扩张成新需求，不在调查中实现代码或重拆 issue。

## 2. 通用调查任务书

每项调查必须包含：问题、固定基线、唯一设计锚点、生产者/消费者、持久化与并发/crash 边界、现有测试覆盖、可复现命令、事实与未决项。报告分为一页摘要和事实附录。若事实与 RFC 冲突，只报告偏离；不能把偏离包装成产品选项。

## 3. R0–R12 gate

| 阶段 | 目的 | 通过 gate |
|---|---|---|
| R0 | 完整读取输入材料 | 输入正文、children、评论、依赖与附件均已覆盖 |
| R1 | source inventory 与能力聚合 | 每段输入有保留/去重/丢弃归宿；形成稳定能力视图 |
| R2 | main 存在性底图 | A–N 每项以真实 checkout/path:line 判定实现、部分实现或缺失 |
| R3 | 把问题改写为地基问题 | 每项只问现有实现能否保留、缺口和接缝，不先选方案 |
| R4 | 供给侧符合性深审 | closure、Git、shape、authorization 四面生产者/消费者闭合 |
| R5 | 核算供给报告 | 事实、建议、矛盾与 unknown 分开；不可信处置不得下传 |
| R6 | 生成待调查细节索引 | 每个 unknown 形成独立、非重叠的调查单元 |
| R7 | 一题一调查 | 每项有复现、路径、因果与确定后果；coverage 与 unknown 清零 |
| R8 | 从事实收敛产品裁决 | 只呈现真实未决语义及完整前因后果；操作员裁决写入 RFC |
| R9 | 建立修补后预期地基 | 对每个已裁缺口定义可验证的最小地基，不实施代码 |
| R10 | 从稳定语义推导原子需求 | 每项需求追溯 RFC 条款，含验证边界且不跨层生长 |
| R11 | 供需匹配与接缝识别 | 每项需求映射到可保留供给、缺口、依赖与跨 issue 接缝 |
| R12 | 滚动重拆 | 只在上游语义与地基稳定后重拆；保持原子 scope 与验收边界 |

## 4. 失败回退条件

出现以下任一情况，退回最近能修正事实的阶段，不向后强推：输入遗漏退 R0/R1；代码证据不足退 R2/R7；报告把建议当需求退 R5；unknown 未闭合退 R6/R7；真实产品语义未裁停在 R8；修补地基依赖未决语义不得进 R9；需求无法追溯 RFC 不得进 R10；接缝或责任边界不清不得进 R12。连续修订方向相反视为振荡，停止并请求操作员明确目标。

“停止在阶段”不是凭空标记 blocked。必须先穷尽已授权调查；只有剩余动作确实需要操作员改变产品语义时才请求裁决，且请求必须给出完整场景、用户可见后果与固定边界。
